# Campus Pulse Dashboard - Project Map

## Project Purpose

Campus Pulse Dashboard is a full-stack student satisfaction analytics project. It collects or generates sample student feedback data, serves that data through a FastAPI backend, and visualizes campus facility satisfaction through an interactive HTML/CSS/JavaScript dashboard.

The project is designed to show the complete path from data creation to analysis, API development, authentication, and frontend visualization.

## High-Level Architecture

```text
Campus_Pulse_Dashboard/
|
|-- backend/       FastAPI application and API routes
|-- data/          CSV dataset and scripts for generating/enriching data
|-- frontend/      Login page and dashboard UI
|-- notebooks/     Exploratory data analysis script
|-- README.md      Main project overview and setup guide
|-- test.py        Small standalone test file
`-- project_map.md Detailed project documentation
```

## Technology Stack

| Layer | Tools |

| Storage | CSV file |
| Authentication | Simple hardcoded admin login plus browser `localStorage` |

## Main User Flow

1. User opens `frontend/login.html`.
2. User enters the admin credentials.
3. Login page sends a `POST` request to `http://127.0.0.1:8000/login`.
4. If credentials are valid, `localStorage.loggedIn` is set to `true`.
5. User is redirected to `frontend/index.html`.
6. Dashboard checks `localStorage.loggedIn`.
7. Dashboard fetches data from the backend.
8. JavaScript calculates chart data and updates the UI.
9. User can apply filters by facility, department, and year.

## Backend Map

### File

`backend/app.py`

### Responsibility

This file defines the FastAPI backend. It loads the CSV dataset into a Pandas DataFrame and exposes API endpoints for the frontend.

### Important Code Behavior

- Loads data from `data/student_satisfaction.csv` when the app starts.
- Enables CORS for all origins so the frontend can call the API from a local HTML file.
- Uses Pandas for summary metrics and filtering.
- Uses hardcoded admin credentials.

### API Endpoints

| Endpoint | Method | Purpose |
| --- | --- | --- |
| `/` | GET | Health/home route that confirms backend is running |
| `/data` | GET | Returns the full dataset as JSON records |
| `/metrics` | GET | Returns total responses, average satisfaction score, and best facility |
| `/filtered` | GET | Returns records filtered by optional facility, department, and year query parameters |
| `/login` | POST | Validates hardcoded admin credentials |

## Frontend Map

### `frontend/login.html`

This is the admin login page.

Main responsibilities:

- Displays the login form.
- Sends username and password to the `/login` API endpoint.
- Shows validation errors for empty or wrong credentials.
- Stores successful login state in `localStorage`.
- Redirects successful users to `index.html`.
- Includes password visibility toggle and Enter-key login support.

### `frontend/index.html`

This is the main analytics dashboard.

Main responsibilities:

- Protects the page with a `localStorage` login check.
- Fetches all dashboard records from `/data`.
- Fetches filtered records from `/filtered`.
- Calculates frontend chart datasets.
- Renders KPI cards and Chart.js charts.
- Supports logout by clearing `localStorage.loggedIn`.

Dashboard sections:

- Total responses metric
- Average satisfaction score metric
- Best facility metric
- Facility, department, and year filters
- Overall satisfaction gauge
- Average score by facility bar chart
- Responses by facility pie chart
- Average score by department horizontal bar chart
- Average score by year line chart
- Satisfaction trend over time line chart

Frontend API base used in JavaScript:

```text
http://127.0.0.1:8000
```

## Data Map

### `data/student_satisfaction.csv`

This is the main dataset used by the backend.

Current columns:

| Column | Meaning |
| --- | --- |
| `student_id` | Unique student/response identifier |
| `gender` | Student gender |
| `year` | Academic year |
| `department` | Student department |
| `facility` | Campus facility being rated |
| `satisfaction_score` | Rating from 1 to 5 |
| `timestamp` | Date and time assigned to the response |

Supported values generated by the scripts:

| Field | Values |
| --- | --- |
| `gender` | Male, Female |
| `year` | 1st Year, 2nd Year, 3rd Year, 4th Year |
| `department` | Engineering, Management, Science, Arts |
| `facility` | Library, Cafeteria, Sports Center, Hostel, WiFi |
| `satisfaction_score` | Integer from 1 to 5 |

### `data/generate_data.py`

Generates 800 synthetic student satisfaction records and writes them to `data/student_satisfaction.csv`.

Run command:

```bash
python data/generate_data.py
```

### `data/add_timestamp.py`

Adds a `timestamp` column to the CSV. It creates random timestamps within the last 60 days and saves the updated dataset.

Run command:

```bash
python data/add_timestamp.py
```

## Setup Workflow

2. Install dependencies.


3. Generate the dataset if needed.

```bash

```

4. Start the backend.

```bash
uvicorn backend.app:app --reload
```

5. Open the frontend.

```text
frontend/login.html
```

## Current Design Decisions

- The backend reads from a CSV file instead of a database.
- The dataset is loaded once when the FastAPI app starts.
- Dashboard chart aggregation is handled in frontend JavaScript.
- Filtering is handled by the backend, then the frontend recalculates charts from the filtered records.
- Authentication is intentionally simple and beginner-friendly.
- CORS is fully open for local development convenience.

## Known Limitations

- Login credentials are hardcoded in `backend/app.py`.
- `localStorage` authentication is not secure for production.
- There is no database, so data changes require CSV regeneration or editing.
- The backend must be restarted if the CSV changes after startup.
- The frontend uses a fixed API URL: `http://127.0.0.1:8000`.
- There is no automated test suite yet.
- The frontend is contained in single large HTML files rather than separated CSS and JavaScript files.

## Good Future Improvements

- Move credentials into environment variables.
- Add real user authentication with JWT or sessions.
- Replace CSV storage with SQLite, PostgreSQL, or MySQL.
- Split frontend CSS and JavaScript into separate files.
- Add API tests for `/data`, `/metrics`, `/filtered`, and `/login`.
- Add frontend error states when the backend is offline.
- Add export options for CSV, Excel, or PDF reports.
- Add deployment configuration for Render, Railway, Vercel, or another hosting platform.
